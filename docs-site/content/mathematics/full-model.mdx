**What it returns.** `forward` returns the logits and a cache (<CodeLine id="forward.return" />). Logits are not probabilities, and `forward` applies no softmax to them. That happens outside, in one of two places:

- **The loss.** `cross_entropy_forward` computes log probabilities from the logits, and returns their exponential as `probs`, in training (<CodeLine id="outside.loss" />) and in validation (<CodeLine id="outside.validation" />). It does not call `softmax_forward`, and computes the same result in log form.
- **The sampler.** `sample_next` calls `softmax_forward` on the logits divided by the temperature (<CodeLine id="outside.sampling" />).

The only `softmax_forward` call inside `forward` turns attention scores into attention weights (<CodeLine id="inside.attention-softmax" />). That is not applied to logits.

Only `loss_and_grads` uses the cache. Validation (<CodeLine id="model.discard-cache-validation" />) and generation (<CodeLine id="model.discard-cache-generate" />) throw it away, though `forward` builds it each time.

## The gradient dictionary

`loss_and_grads` starts by making one array of zeros per parameter, under the same key and with the same shape:

<CodeStep id="model.grads-zero" />

Every backward step then adds to that dictionary. It adds in place, so `block_backward` and `embed_backward` return without handing `grads` back: their caller's dictionary already holds the result. The head and the final LayerNorm are added by `loss_and_grads` itself, and the gradient that goes on to the next step travels separately, as `dX`.

Within one call each key is written at one place in the code. Only `tok_emb` can receive several additions there: `embed_backward` adds one row per position, so a repeated id accumulates.

Because the keys match, `Adam.step` can look up the gradient of each parameter by name. A test checks that the keys and shapes match (<CodeLine id="model.grads-shape-test" />).

## Parameter keys

The dictionary is flat: one string key per array. The keys follow three rules:

- **A suffix per array.** The feed-forward layers and the head end in `_w` for weights and `_b` for biases. A LayerNorm ends in `_g` for its scale and `_b` for its shift.
- **Attention's four projections come from a loop** over `q`, `k`, `v` and `o`, so `"w" + n` gives `wq` and `"b" + n` gives `bq`, and so on (<CodeLine id="attention.params" />).
- **Block entries start with a prefix** that holds the block index, counted from 0 (<CodeLine id="model.key" />). `block_forward` and `block_backward` build the same prefix (<CodeLine id="model.key-block" />), so `b0.wq` is the query weights of the first block. The PDF writes this prefix `bl.` (p. 9). This site follows the code.

The table lists each name once, with `b{l}.` standing for every block. Names and shapes come from calling `init_params`. `head_w` is a separate matrix, not tied to `tok_emb`.
