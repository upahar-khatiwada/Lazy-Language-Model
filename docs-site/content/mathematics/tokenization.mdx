The tokenizer turns text into the integer ids the model reads. It learns from the text itself, by repeatedly merging the most frequent adjacent pair of tokens.

## What this code does

The method is called byte pair encoding, but this code works on characters, not bytes. `list(word)` splits a pre-token into Unicode characters (<CodeLine id="tokenizer.chars" />). Nothing here touches UTF-8 bytes.

| Feature                         | In this code                                                |
| ------------------------------- | ----------------------------------------------------------- |
| Starting tokens                 | Unicode characters of the text, not byte values             |
| Characters not seen in training | Each maps to the unknown token, id 0                        |
| Case                            | Preserved. No lower-casing, so `The` and `the` are distinct |
| Padding, start and end tokens   | Not available from the implementation                       |

`train.main` passes <ConfigValue name="num_merges" /> as the limit on merges (<CodeLine id="train.tokenizer" />). That is a maximum, because training stops early if no pair is left (<CodeLine id="tokenizer.stop" />). The default in the function signature, `max_merges=1000`, is not used by training.

<Callout kind="source">

The reference PDF differs from the code here, and this page follows the code. Its pattern lets a word carry its leading space, and it lower-cases the text. In the code, a space is always its own pre-token and case is preserved. The full list is on <PageLink page="reference/sources-discrepancies">Sources & Discrepancies</PageLink>.

</Callout>

The tokenizer has no backward pass. Training the merges only counts, and the model's gradients stop at the embedding table.

## Pre-tokens and word counts

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="tokenizer.count_words" split />

The pattern has three alternatives, tried in order:

- `\w+`: one or more word characters. On Python strings these are Unicode letters and digits, plus the underscore.
- `\s`: exactly one whitespace character. Two spaces make two pre-tokens.
- `[^\w\s]`: exactly one character that is neither of those, such as punctuation.

Every character matches one of the three, so no character is dropped.

<ConceptStep>Why does the model need it?</ConceptStep>

<ConceptWhy concept="tokenizer.count_words" />

Whitespace and punctuation pre-tokens are always one character long, so they have no inner pair. As a result, every merge in this tokenizer happens inside a run of word characters, and a merged token never contains a space or punctuation.

## Encode and decode

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="tokenizer.Tokenizer.encode" split />

The unknown token works like this (<CodeLine id="tokenizer.unk" />):

- Only a character that was not in the training text can be missing from the vocabulary. Merged tokens and seen characters are all listed.
- Each unseen character becomes its own id 0. `zzz` gives three ids, and a word keeps its known part: `lowz` gives the id of `low`, then 0.
- `decode` turns id 0 into the literal string `<unk>`, so the original character is lost. `decode(encode(x))` returns `x` only when every character of `x` was seen in training.
- The text `<unk>` is not special. It is five characters, and each is looked up on its own.
- `train.main` builds the tokenizer from the same text it encodes, so every character is known and id 0 does not occur in the training ids. It can occur in a prompt given to `talk.py`.
