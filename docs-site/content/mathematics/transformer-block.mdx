A block has two branches: attention and a feed-forward network. This page covers the feed-forward network, how `block_forward` joins the two branches, how `block_backward` reverses that, and what the forward pass leaves behind for the backward pass.

The numbers on this page are labelled Illustrative Example. The tiny model below has random parameters from the real `init_params`, not learned values. The real sizes appear under Tensor shapes.

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="transformer.block_forward" split />

This form is called pre-LN because of where the LayerNorm sits in the code. Each one runs before its sub-layer: the first on the line before attention (<CodeLine id="ln.block-first" />, <CodeLine id="attention.call" />), and the second on the line before the feed-forward layer (<CodeLine id="ln.block-second" />, <CodeLine id="block.ffn-call" />).

## Residual connections in the backward pass

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="transformer.block_backward" split />

<ConceptStep>Why does the model need it?</ConceptStep>

<ConceptWhy concept="transformer.block_backward" />

<Callout kind="note">

In general, a path that passes the gradient on unchanged gives earlier layers a gradient that does not have to shrink through every layer on its way there. This is a general explanation. Nothing in this repository measures that effect.

</Callout>

**What each branch receives.** Each branch's output is one term of a sum, and the derivative of a sum with respect to one term is the identity. So the feed-forward backward receives `dY` as it is, and attention's backward receives `dX1` as it is.

<MathBlock id="block.back.terms" />

**Why the identity path carries the gradient unchanged.** `X1` reaches `Y` by two routes: directly, and through the branch. The direct route is an add, whose derivative is the identity, so multiplying `dY` by it leaves `dY` as it was. That is the term `dY` on the line `dX1 = dY + dX1_branch`. The branch route adds the other term.

<ConceptStep>Where is it used?</ConceptStep>

`loss_and_grads` calls it once per layer, last block first (<CodeLine id="block.back-call" />). No test calls it directly. `test_every_tensor_passes` reaches it through the whole model.

<Trace concept="transformer.block_backward" />

**How this reaches a parameter update.** `block_backward` stores nothing itself except the two LayerNorms' gradients (<CodeLine id="update.ln2" />, <CodeLine id="update.ln1" />). The branch functions fill the rest of `grads`. The optimizer then uses them, through the same steps as above: <CodeLine id="train.gradient" />, <CodeLine id="train.clip" /> and <CodeLine id="train.adamw" />. `dX` is returned (<CodeLine id="update.residual" />). It becomes the `dY` of the block before this one, or goes to `embed_backward` after the first block.

## Caches

The forward pass returns each cache alongside its output, because the backward pass needs values it cannot get otherwise. `block_forward` collects four of them in one dictionary. `block_backward` reads each one once, in reverse order:

<CacheTable rows="block" />

The backward functions read parameters from `params`, not from a cache. `block_forward` leaves `att`, `ff`, `X` and `X1` out of its caches, because no backward function reads them. In the code, both the feed-forward cache and the attention cache have a key named `A`. They hold different arrays.
