Attention is the part of a block where positions exchange information. This page goes through `attention_forward` line by line, then `attention_backward`. Every equation links to the code that computes it, and every Illustrative Example is computed from that code's mirror.

## Why attention?

A linear layer treats each row on its own: row `t` of its output depends only on row `t` of its input. A model that predicts the next token also needs earlier tokens to affect the current one. Attention does this by building each output row from a weighted mix of rows at that position and earlier ones. The weights are computed from the input, so they differ from one sequence to the next.

In general, these three names are explained with a question for each one:

- **Query:** what am I looking for?
- **Key:** what do I contain?
- **Value:** what do I hand over?

Those questions are a way to remember the roles. They are not something this project computes. In the code, a query, a key and a value are three linear projections of one input. A query times a key gives a score, and the scores decide how the values are mixed.

**The example on this page.** The sentence is "The cat sat on the mat", with one row per word and hand-picked numbers: `T = 6`, `d = 4` and `H = 2`, so `d_h = 2`. Every number in this example is labelled Illustrative Example. The real model works differently: it reads sub-word tokens, not words, and it has `H =` <ConfigValue name="num_heads" /> heads of width `d_h =` <ConfigValue name="head_dim" />, inside rows of width `d =` <ConfigValue name="emb_dim" />. Nothing written on this page says what the trained model attends to. The only real numbers are the exported weights of one window, under Actual Model Output, when an export exists.

## The transformer.py implementation

This is the whole function, with its real line numbers. Highlighted lines have a link record behind them.

<CodeReference symbol="transformer.attention_forward" />

Two things to note when reading it:

- `S` is assigned twice. The first assignment holds the scaled scores, and the second overwrites them with the masked scores.
- The returned dictionary is the cache that the backward pass reads. It holds `Xn`, `Qh`, `Kh`, `Vh`, `A` and `O`. It does not hold `S`, `Q`, `K` or `V`.

Then it goes back through softmax, to the scores:

<MathBlock id="attention.back.ds" />

**Why masked positions get no gradient.** `softmax_backward` multiplies its result by the weights. A masked position has a weight of exactly 0, so whatever `dA` holds in that cell, `dS` is exactly 0 there. Its contribution to `dVh` is also 0, because `A^T` carries the same 0. The rest of the backward pass adds nothing from that cell, so the output at a position sends no gradient to any later position.

<MathBlock id="attention.back.masked" />

From the scores, the gradient goes to the queries and keys. The scale appears again here, because the forward pass divided by it:

<MathBlock id="attention.back.dk" />

Each of the three projections is a linear layer of the same input. So each gets a parameter gradient, and the gradients on the input add up:

<MathBlock id="attention.back.dw" />

<MathBlock id="attention.back.db" />

## Role in the model

Attention is the first branch of each block. `block_forward` normalizes its input, runs attention on that copy, and adds the result to the unnormalized input:

<CodeStep id="attention.residual" />

The model has <ConfigValue name="num_layers" /> blocks, and each has its own eight attention parameters:

<ParameterTable
  names={["b{l}.wq", "b{l}.bq", "b{l}.wk", "b{l}.bk", "b{l}.wv", "b{l}.bv", "b{l}.wo", "b{l}.bo"]}

Attention is the only step in a block that moves information between positions. The feed-forward layer that follows works on each row alone. Because the mask is applied in every block, the output at a position depends only on that position and earlier ones, all the way through the model. A test checks this on the whole model, by changing only the last token and comparing the earlier logits (<CodeLine id="attention.future-test" />).
