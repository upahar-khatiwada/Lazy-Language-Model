## Next-token prediction

Training has one objective: at each position of a window, predict the next token. For input `x[t]`, the correct answer is `y[t]`, the id right after it in the stream. A causal mask in <PageLink page="mathematics/attention">attention</PageLink> stops a position from reading later ones, so the prediction at `t` can only use `x[0]` to `x[t]`. <PageLink page="mathematics/softmax-cross-entropy">Softmax & Cross-Entropy</PageLink> covers how the model is scored on each answer.

<Callout kind="note">

In general, the probability of a whole sequence can be written as a product, over positions, of each token's probability given the tokens before it. The PDF states this as Eq. 61. This code never computes that product. It computes a mean cross-entropy over windows of at most <ConfigValue name="seq_len" /> tokens.

</Callout>

## Text to ids

`load_corpus` reads one column of a CSV file. In `config.py` the file is <ConfigValue name="corpus_path" />, the column is <ConfigValue name="corpus_column" />, and at most <ConfigValue name="max_rows" /> rows are read.

- A column that does not exist raises `ValueError`.
- `max_rows` limits the rows read from the file, before missing values are dropped.
- Each remaining row is stripped of surrounding whitespace.
- All rows are joined with newlines, and one final newline is added.

The result is a single string. Rows have no other boundary in it, so a window can run from the end of one row into the start of the next, and the model sees the newline as a token.

## The split

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="data.split_ids" split />

<ConceptStep>Why does the model need it?</ConceptStep>

<ConceptWhy concept="data.split_ids" />

Windows overlap, so the order matters. If `train.main` made windows first and split them afterwards, the windows around the cut would hold ids from both sides, and validation would partly test on training text. Splitting first removes those windows, at the cost of fewer windows overall.

## Shuffling and batching

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="data.iterate_batches" split />

`train.main` creates one generator from <ConfigValue name="seed" /> (<CodeLine id="train.seed" />) and uses it for everything random. `iterate_batches` receives it once per epoch and passes it to pandas, which moves the generator along. So each epoch gets a new order, and a repeated run with the same settings gets the same orders.
