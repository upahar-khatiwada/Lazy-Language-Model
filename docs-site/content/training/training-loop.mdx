## Mini-batch gradient

<ConceptStep>What is it?</ConceptStep>

<ConceptCard concept="train.batch_loss_and_grads" split />

<ConceptStep>Why does the model need it?</ConceptStep>

<ConceptWhy concept="train.batch_loss_and_grads" />

In general, one window's gradient depends a lot on which tokens happen to be in it. Averaging over `B` windows keeps what those gradients share, and differences between windows partly cancel, so the update changes less from one step to the next. That is general reasoning, not something this project measures.

## The sample printed each epoch

After validation, `train.main` generates a short text so that a person can look at it. Nothing reads the result.

<CodeStep id="train.sample" />

- **The seed tokens are the first 3 tokens of the first validation window**, `va_x.iloc[0][:3]`. So the seed is the same on every epoch.
- **It generates 30 new tokens.** This is a literal in the call, and `max_new_tokens` in `config.py` is not used here. It applies only to `talk.py`.
- **The window, temperature, `top_k` and `top_p` come from `config.py`:** `seq_len` is <ConfigValue name="seq_len" />, `temperature` is <ConfigValue name="temperature" />, `top_k` is <ConfigValue name="top_k" /> and `top_p` is <ConfigValue name="top_p" />.
- **The printed text includes the seed.** `generate` returns the seed ids followed by the new ids, and `tok.decode(out)` decodes them all. `repr` shows newlines as `\n` and adds quotes.
- **It uses the same `rng` as the batch shuffling** (<CodeLine id="loop.shuffle-rng" />). So drawing the sample changes the order of the next epoch's batches.

<PageLink page="generation/sampling">Sampling</PageLink> and
<PageLink page="generation/autoregressive-generation">Autoregressive Generation</PageLink> explain
how the tokens are chosen.

## Logging lines

`train.py` prints these lines, and nothing else. The output column comes from evaluating the file's own format strings with the values of one real step on a hand-picked text and a tiny model. The sampled ids are stored from one earlier run of `generate`. It is not output from a training run.

## Checkpoint

After the last epoch, `train.main` saves the model once. It saves nothing during training, so stopping a run early leaves no checkpoint from that run.

<CodeStep id="train.checkpoint" />

`save_checkpoint` writes three files with the same prefix: the weights, the model shape and the tokenizer. When `train.py` runs as a script, the prefix is always the default, `checkpoints/model`, because the file calls `main()` with no arguments. <PageLink page="code/checkpoints-tests">Checkpoints & Tests</PageLink> documents the files.
